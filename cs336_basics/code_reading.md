## 1. 先认识三个程序

### 1.1 一个故事如何变成模型能处理的东西

人看到的是文字；这套模型接收的是整数编号。把文字变成编号的工具叫 tokenizer，中文
通常叫分词器。

**token** 是词表中的一个单位。它可能对应一个完整单词、一部分单词、空白、标点或一
段字节。不要把“token 数”直接当成“英文单词数”或“字符数”。

**token ID** 是这个单位在词表中的整数编号。编号本身没有大小意义：编号 100 的内容
不会天然比编号 10 的内容重要十倍。

这三个文件承担的工作如下。

| 文件 | 接收什么 | 主要做什么 | 留下什么 |
|---|---|---|---|
| `prepare_tokens.py` | 文本、已有词表、已有合并规则 | 分段编码、核对、写入数组 | token `.npy` 文件和说明用 `.json` 文件 |
| `train.py` | 训练与验证 token 数组，或人工序列 | 取样、预测、计算误差、更新参数 | `config.json`、`metrics.jsonl`、`last.pt` |
| `generation.py` | 配置、检查点、分词器和故事开头 | 反复预测并选择下一个 token | 终端显示的故事和进程内历史 |

`prepare_tokens.py` 使用已经训练好的 tokenizer，不在这里学习 BPE 合并规则。
`train.py` 训练语言模型参数；`generation.py` 使用这些参数，不执行参数更新。

### 1.2 三种常见文件不要混淆

| 文件类型 | 可以把它理解成 | 本项目用途 |
|---|---|---|
| JSON | 一份结构化文字记录 | 词表、合并规则、实验配置、编码统计 |
| JSONL | 每一行都是一份独立 JSON 记录 | 随时间追加的训练事件 |
| NPY | 带类型与形状说明的 NumPy 数组文件 | 一条连续的 token ID 序列 |
| PT | 由 PyTorch 序列化保存的对象 | 模型状态、优化器状态、已完成更新次数 |

文件扩展名只是名称约定。真正能否读取，还要看内部内容。原始 ID 字节文件改名成
`.npy`，不会自动拥有 NPY 文件头。

### 1.3 读一个函数时，始终问四件事

1. **输入**：参数是什么类型、什么形状、什么单位？
2. **输出**：返回的是数值、列表、模型、统计字典，还是没有显式返回？
3. **副作用**：是否修改模型、随机状态、文件或终端显示？
4. **前提**：什么时候有意义，哪些输入会报错？

例如 `format_duration` 主要做格式转换；`train_step` 会修改模型和优化器；
`encode_to_raw` 会写文件；它们不能只按“都有一个函数名”来理解。

## 2. Python 与文件操作基础

### 2.1 名字、对象、类型

变量名指向一个对象。对象有类型，例如整数、字符串、列表或模型对象。

| 名称 | 含义 | 本文里的典型用途 |
|---|---|---|
| `int` | 整数 | token ID、步数、计数 |
| `float` | 浮点数 | 学习率、损失、耗时 |
| `str` | Unicode 文本字符串 | 文件路径文字、故事正文 |
| `bytes` | 字节序列 | 文件二进制内容、token 对应的字节 |
| `bool` | 真或假 | 是否结束、是否恢复训练 |
| `None` | 没有提供值或尚无结果 | 未指定文档上限、尚无故事历史 |
| `list` | 有顺序、可以修改的序列 | prompt ID、参数名列表 |
| `tuple` | 有顺序、不能原地改元素的序列 | 数组形状、两个 beta 值 |
| `dict` | 按键查值的映射 | 配置、日志、检查点 |
| `set` | 不重复元素的集合 | 检查实际 ID 集合是否完整 |

`None` 不等于数字 0。未知剩余时间和剩余 0 秒，也不是同一种状态。

列表复制尤其值得注意：两个名字可以指向同一个列表；对其中一个名字追加元素，另一个
名字也会观察到变化。生成函数使用 `list` 复制 prompt 的外层列表，随后追加不会改动
调用者原来的列表。这里的元素是整数，浅复制已经满足这一用途。

### 2.2 读取语句的基本顺序

普通语句从上到下执行。缩进决定哪些语句属于函数、循环或条件分支；空行帮助阅读，不
负责决定逻辑。

`import` 导入模块；`from ... import ...` 从模块中取得名字；`as np` 给 NumPy 取简
短别名。`cs336_basics` 开头的导入指向你的本地包，不意味着导入的是 PyTorch 官方版
本的同名函数。

`def` 定义函数。读到函数定义时，一般只是建立函数对象，不会立即执行函数体。调用时
才进入函数体。函数参数是接收输入的局部名字；调用者提供的具体值叫实参。

带名字的参数用于明确“这个值送到哪个参数”；位置参数则按顺序对应。默认参数表示调用
时不提供该项会采用什么值。`return` 结束当前函数并把结果交还调用者；多个返回值在
这里由元组承载，调用者再按顺序拆开。

三个文件最后的 `__name__` 判断负责区分直接执行与被导入。直接作为入口运行时进入
`main`；作为模块导入时，不因此自动进入交互或训练主流程。导入仍会执行顶层导入和常
量定义，并非完全没有动作。

### 2.3 控制流程词汇

| 写法中的关键词 | 阅读方式 |
|---|---|
| `if` / `elif` / `else` | 按条件选择分支 |
| `for` | 从一个可迭代对象中逐项取值 |
| `while` | 条件保持为真时重复 |
| `break` | 退出最近一层循环 |
| `continue` | 跳过本轮剩余工作，进入下一轮 |
| `return` | 退出整个当前函数 |
| `raise` | 抛出异常，让正常流程中断 |
| `try` / `except` | 尝试执行，并处理匹配的异常 |
| `finally` | 正常结束或异常离开时都执行清理 |
| `with` | 在进入与离开一个作用域时管理资源或状态 |
| `yield` | 交出一项结果并暂停；下次请求时从这里恢复 |

`try` 中已经决定返回结果，仍会先执行 `finally`。这一点决定验证函数能否正确恢复模
型模式和随机状态。

`ValueError` 通常表示值不合要求；`FileNotFoundError` 表示文件或路径不存在；
`FileExistsError` 表示本来要求新建却发现已存在；`RuntimeError` 表示运行过程遇到
不能继续的状态；`OSError` 与系统 I/O 等错误有关。

### 2.4 运算符与真假判断

| 符号或用法 | 含义及这里的用途 |
|---|---|
| `=` | 绑定名字或写入一个位置，不是判断相等 |
| `==`、`!=` | 比较是否相等、是否不同 |
| `is None` | 判断是不是表示缺失的那个 `None` 对象 |
| `<`、`<=`、`>`、`>=` | 大小比较 |
| `and`、`or`、`not` | 且、或、否定；`and`、`or` 会短路 |
| `%` | 余数；也用于判断计数是否到达固定间隔 |
| `//` | 向下取整的除法；维度已验证整除后就是每头维度 |
| `/` | 数字相除；对 `Path` 对象则被定义为拼接路径 |
| `+=` | 更新累计值；对列表等可变类型还要注意原地变化 |
| `in` | 判断成员是否存在 |

空列表、空字符串、数字 0、`None` 在条件中都按假处理，但含义不同。一个只含空格的
字符串并不为空；经过 `strip` 去掉首尾空白后可能变为空。

链式比较表示同时满足相邻条件，例如本文件的 top-p 范围要求是“大于 0，并且小于等于
1”。短路的意思是：已经能够确定结果时，不再计算后面的条件。这有助于先排除
`None`，再比较数值。

### 2.5 下标、切片与形状元组

下标通常从 0 开始，负下标从末尾倒数。`-1` 是最后一项。切片左端包含、右端不包含；
省略左端表示从开头，省略右端表示直到末尾。

以五项序列 A、B、C、D、E 为例：区间 [1, 4) 得到 B、C、D；最后两项得到 D、E。对普
通序列做切片时，终点超过长度通常会截到实际末尾，不因此报错。

`shape` 用元组表示各轴长度。`(N,)` 表示一维、有 N 项；单元素元组的逗号具有语法意
义。`(1, T)` 表示两维，第一维长 1，第二维长 T。维度多一个，不代表凭空多出很多
数；也可能只是增加组织层次。

### 2.6 迭代器与生成器：不一次拿出所有内容

列表通常已经保存所有元素。迭代器强调“下一项怎么取得”；生成器是实现迭代器的一种方
式。

调用含 `yield` 的函数时，得到一个生成器对象。消费者开始请求内容，函数体才推进；
遇到 `yield` 暂停并保留当前局部状态。再次请求时继续。耗尽后，不能指望同一个对象
自动从头再来。

在数据准备中，外层处理一段文档时，内部才按需读取文本块。`islice` 限制最多交出多
少段，不会先把整个文档流变成列表。不过读取仍以块为单位，底层可能已经读到了本次上
限之外的一部分字符。

模型的 `parameters` 也提供可迭代的参数序列。`next` 取当前迭代器的下一项；生成代
码用第一项参数的设备推断输入应放在哪个设备上。

### 2.7 文件路径与“工作目录”

**工作目录**是程序解释相对路径时使用的起点，未必是脚本所在目录。编辑器启动配置可
以影响它。

`Path` 把路径变成对象；`resolve` 得到解析后的绝对路径；`parent` 是上一级，
`parents[0]` 是上一级，`parents[1]` 是再上一级。`name` 是文件名，`suffix` 是最后
一个扩展名，`with_name` 换文件名而保留所在目录。

`exists` 问路径是否存在；`is_file` 问是否为文件；`is_dir` 问是否为目录。`stat`
取得文件信息，其中 `st_size` 是字节数，`st_mtime_ns` 是纳秒单位的修改时间记录。
`mkdir` 建目录，`rename` 重命名或移动，`unlink` 删除文件。详细 API 可查
[Python pathlib 文档](https://docs.python.org/3/library/pathlib.html)。

这些方法名中，有些只构造一个路径对象，有些真的修改磁盘。比如 `with_name` 不会重
命名文件；`rename` 才会。

### 2.8 打开文件与数据格式

| 模式 | 意义 | 当前脚本的用途 |
|---|---|---|
| `r` | 读取文本 | 文本源文件、JSON |
| `rb` | 读取原始字节 | 计算摘要、复制 ID 数据 |
| `w` | 写文本，已有文件会截断 | 新实验配置 |
| `a` | 在末尾追加文本 | 训练日志 |
| `x` | 仅新建文本文件，存在则报错 | 编码元数据 |

`with` 管理打开的文件，使正常离开或报错离开时都关闭文件。文本模式的 `encoding`
指定字节与文字如何转换。`newline=""` 在这里保留读到的换行形式，避免 Windows 换行

`read` 读取内容；文本模式的数量按字符解释，二进制模式按字节解释。`write` 写内

`json.load` 从文件读成对象，`json.dump` 将对象写到文件；`json.dumps` 得到 JSON

### 2.9 命令行参数与输出格式

`ArgumentParser` 保存参数规则；`add_argument` 登记一个参数；`parse_args` 读取实

## 3. 数组、张量与语言模型基础

### 3.1 字符、字节、token 是三个计量系统

文本“猫”在 Python 字符串中是一个 Unicode 码点，UTF-8 编码通常占三个字节。
tokenizer 如何把它分成 token，还取决于词表和合并规则。更复杂的可见字符也可能由多
个 Unicode 码点组成。

因此，这些量不能互换：原始文件字节数、字符串长度、token 数量、存放 ID 所需字节
数。

当 ID 用两字节无符号整数保存时，一百万个 ID 的原始数据区是两百万字节；NPY 文件还
要加文件头。token 对应的原文字节有多长，不会改变单个 ID 在这个存储格式中占两字节
的事实。

### 3.2 NumPy 数组与 PyTorch 张量

NumPy 数组用于紧凑数值存储与处理。PyTorch 张量也保存数值，还参与设备计算与自动求
导。

理解张量时，同时看三个信息：

| 信息 | 回答的问题 | 例子 |
|---|---|---|
| `shape` | 按几个轴组织，每个轴多长 | `(4, 16)` |
| `dtype` | 每个数如何表示 | `uint16`、`int64`、`float32` |
| `device` | 数值位于哪类计算设备 | CPU 或 CUDA GPU |

`uint16` 的范围是 0 到 65535。若 ID 从 0 开始连续编号，最多能容纳 65536 个不同
ID。`torch.long` 是这里传给模型的 64 位整数类型；`torch.float32` 用于模型浮点参
数。紧凑磁盘存储与计算时的数据类型可以不同。

### 3.3 本教程反复使用的形状符号

| 符号 | 意义 |
|---|---|
| N | 整个数据数组的 token 数 |
| B | batch size，一批同时处理多少条序列 |
| T | 当前每条序列的输入长度 |
| V | vocabulary size，词表大小 |
| D | d_model，每个位置的隐藏向量长度 |

训练输入 `x` 的形状是 `(B, T)`，每项是一个 ID；目标 `y` 也是 `(B, T)`；输出
`logits` 是 `(B, T, V)`，表示每条序列、每个位置对全部候选 token 的分数。

假设 B 为 2、T 为 3、V 为 5，那么输入有 6 个 ID，输出有 30 个分数。输出最后一维
的 5 个数共同描述一次“接下来是哪种 token”的预测，不能把这 5 个数当成连续五个生成
token。

### 3.4 为什么目标比输入向后错一个位置

假设一小段数据是 A、B、C、D、E，某次长度为 3 的输入取 A、B、C，对应目标就是 B、
C、D。

| 输入位置 | 模型在这个位置应预测什么 |
|---|---|
| A 所在位置 | B |
| B 所在位置 | C |
| C 所在位置 | D |

这里每个位置都参与训练，所以至少需要 T+1 个源 token，才能组织一条长度 T 的输入及
其目标。训练脚本没有在这里手工制作因果掩码；因果约束由它调用的模型内部承担。因果
的意思是当前位置不能借助未来内容预测未来。

### 3.5 logits、概率和损失

**logits** 是模型输出的原始实数分数，不保证非负，也不保证总和为 1。

**softmax** 把同一次预测的一组分数变成概率：每项非负、总和约为 1。对所有分数同时
减去同一个数，不改变理论上的 softmax 概率；这给数值稳定处理提供了空间。

**交叉熵损失** 衡量模型给真实下一个 token 分配的概率有多小。对单个位置，损失等于
真实 token 概率的负自然对数。真实概率为 0.5 时约为 0.693，为 0.1 时约为 2.303。
平均损失低，表示模型对正确目标的整体预测更好；它不是“错误 token 的数量”。

当前本地 `cross_entropy` 直接接收 logits，不要求调用者先做 softmax，并对 batch
与时间位置求平均，返回标量张量。零维标量张量的形状是 `()`。

### 3.6 参数、梯度、优化器分别负责什么

**参数**是模型里可学习的数值。**梯度**描述损失在当前位置对参数变化的局部敏感程
度。**计算图**记录前向运算之间的依赖，使自动求导能够回溯。**优化器**结合梯度、学
习率以及自身历史状态更新参数。

这解释了三个不同动作：模型前向给出预测；`backward` 计算梯度；优化器 `step` 才修
改参数。学习率控制每次更新的尺度，但 AdamW 还使用历史梯度信息，因此不能简单把它
理解成所有参数统一减去同样的数。

默认情况下梯度会累积，这也是每步先清理上一轮梯度的原因。梯度裁剪控制梯度整体范
数，不能把 NaN 自动变成正常值。

### 3.7 模式切换与关闭求导是两回事

| 操作 | 主要意义 | 会自动更新参数吗 |
|---|---|---|
| `model.train` | 切到训练模式 | 不会 |
| `model.eval` | 切到评估模式，影响依赖模式的层 | 不会 |
| `torch.no_grad` | 在作用域内关闭梯度记录 | 不会 |
| `torch.inference_mode` | 面向推理，进一步减少自动求导相关开销 | 不会 |

评估模式本身不等于关闭求导。推理模式也不会替你执行 `eval`。生成文件同时做这两件
事有不同目的。`inference_mode` 对其中创建的张量有额外限制，不能把它泛化成训练中
任意位置都可用的提速开关。参见
[PyTorch inference_mode 文档](https://docs.pytorch.org/docs/stable/generated/torch.autograd.grad_mode.inference_mode.html)。

### 3.8 随机种子与随机状态

种子可以理解成伪随机序列的起点，随机状态则包括当前走到了哪里。设置同一个起点有助
于重复实验，但从中已经抽过多少次同样重要。

Python、NumPy、PyTorch 各自有随机机制。训练脚本分别设置种子，因为数据采样和模型
初始化未必使用同一个库。固定种子也不保证跨设备、跨版本、跨平台逐位一致。参见
[PyTorch 可复现性说明](https://docs.pytorch.org/docs/stable/notes/randomness.html)。

#### pending 保存什么

`pending` 保存已经读到、但还没有作为完整段交出去的文字。新块到来时接在后面。
`start` 标记本次尚未交出部分的起点。

`find` 从指定位置寻找完整分隔符，找不到时返回 -1。找到时，`position` 指向分隔符

交出一段之后，起点移动到这段末尾。内层循环继续寻找，所以一个读取块里包含多个文档
也能逐个交出。找不到更多完整分隔符时，只留下未交出的尾部；下一块会继续补到它后
面。

#### 看一个跨块的纸面例子

| 到达的数据 | 此时能交出的段 | 留给下一次的尾部 |
|---|---|---|
| `甲<\|endo` | 无 | `甲<\|endo` |
| `ftext\|>乙<\|endoftext\|>丙` | `甲<\|endoftext\|>`、`乙<\|endoftext\|>` | `丙` |
| 文件结束 | `丙` | 无 |

这展示了三个行为：跨块分隔符会被重新拼完整；同一块能产生多段；最终没有分隔符的尾
部也保留。

结尾的 `if pending` 仅排除真正空字符串。它没有 `strip`，所以纯空白尾部也保留。这
样才能进行后面的精确还原和字节计数。

#### “流式”有什么边界

整个数据集没有一次性积存在内存中，但当前未结束的文档会保留在 `pending`。如果整个
文件都没有分隔符，它可能增长到整个文件大小。编码时还会存在当前文档的 ID 列表、数
组与字节数据。因此“读取块只有 65536 字符”不等于“内存最多只用 65536 字符”。

`document_segments` 统计的是这里交出的段数。一个只含分隔符的段、最终空白尾部，都
可能算一段；它未必等于人类认定的故事篇数。

### 5.6 补读 get_batch 的调用契约

虽然定义在 `data.py`，不弄清它就无法理解训练输入。

当前实现由 NumPy 随机选择 B 个起点，然后分别取长度 T 的输入和向右偏移一个位置的
目标，叠成批次，最后转换为指定设备上的 `torch.long` 张量。

假设 N 为 8、T 为 3，可用起点为 0 到 4，一共 5 个；起点 4 的目标仍能包含下标 7
的最后一项。随机抽样允许重复，批次也可能互相重叠。

因此这里没有“逐条不重复遍历完整数据集”的 epoch 循环。`steps` 表示随机抽取批次并
执行更新的次数，不表示完整看过数据集多少遍。

### 5.7 第 188—242 行：train_step

**输入**是模型、优化器、一个批次的输入与目标、参数配置和更新索引；**输出**是
Python 数字形式的损失与学习率；**副作用**包括梯度、模型参数和优化器历史状态的变
化。

#### 第 189—202 行：本次更新采用哪个学习率

这里的 `iteration` 是进入这一步之前已经完成的更新次数，第一次为 0。调度函数依据
这一索引和四个调度参数返回一个浮点学习率。

核对当前 `schedules.py` 后，可以读出三个阶段：预热时从较小值升高，到预热边界达到
峰值；之后按余弦变化降至最小值；超过结束索引后保持最小值。

以默认参数为例：

| 更新索引 | 学习率行为 |
|---:|---|
| 0 | 为 0，因为默认存在预热 |
| 1 | 峰值的五分之一 |
| 5 | 到达峰值 0.001 |
| 200 | 到达 0.0001 |
| 大于 200 | 保持 0.0001 |

默认目标总步数是 50，所以默认训练不会跑完整个到 200 的余弦阶段。若预热长度为 0，
则第一次不进入预热分支，这与默认情况不同。

`optimizer.param_groups` 是参数组列表，每组是一个字典。遍历它并修改 `lr`，使后面
的 `optimizer.step` 使用本步学习率。优化器构造时传过一次学习率，不代表它之后不能
变化。

#### 第 204—213 行：清理、前向、损失

`zero_grad` 清理之前残留的梯度，不是把模型参数清零。随后 `model(x)` 调用模型的前
向计算，取得 logits；`cross_entropy` 把它与 y 比较，得到平均损失。

在默认配置中，x 与 y 都为 `(4,16)`，logits 为 `(4,16,6)`，loss 为标量。这三个形
状能从接口推导出来，不需要记忆每个文件的全部内容。

模型对象可以像函数一样调用，是因为它继承的 PyTorch 模块提供了调用机制并转到
`forward`，不是说 `model` 本身就是一个普通函数定义。

#### 第 215—230 行：有限性与反向传播

`torch.isfinite` 对每个数判断是否既不是 NaN，也不是正负无穷。loss 只有一个元素，
因此 `.item` 可以把真假值取成 Python 标量，供条件分支使用。

`loss.backward` 根据计算图求出参数梯度，写到相应参数的 `.grad`。之后遍历模型参
数，只检查已有梯度的参数。

参数梯度通常有很多元素，所以先 `isfinite` 得到同形状布尔张量，再 `.all` 合并为“
是否全部有限”，最后 `.item` 取出单个布尔值。不能对任意多元素张量直接用 `.item`
获取所有内容。

`grad is None` 表示没有保存梯度，与“梯度是一张全零张量”不同。无论是未参与该次计
算还是尚未产生梯度，都不能直接当作数值零去读取其元素。

#### 第 232—242 行：裁剪、更新、返回

当前 `gradient_clipping` 汇总全部已有梯度的 L2 范数；超过阈值时按同一比例缩放。
L2 范数是“所有梯度元素平方和的平方根”，不是每个元素逐一截断。

纸面上若只有两个梯度元素 3 和 4，整体范数是 5。阈值为 1 时，全局缩放会让方向保持
一致，而不是只把两个元素分别压到 1。

`optimizer.step` 才执行参数更新。当前 AdamW 还维护每个参数的历史状态，因此即便第
一步学习率为 0，这次调用仍可推进优化器内部计数与历史；不能因为参数数值未移动就认
为整个步骤什么都没做。

返回的 `loss.item` 是**本次更新前那次前向计算的损失**，没有在更新之后再计算一
遍。后面的日志是在更新完成后记录它，因此日志的时间点与这个损失对应的权重时刻要区
分。

每个批次的 B 和 T 相同，所以“各批平均损失再平均”等于“把这批次集合中的所有位置损

**理解检查：** 验证结果改变，至少可能来自权重改变、数据或配置改变、数值环境变
化。固定采样窗口只是减少其中一类变化来源，不等于所有结果必然一致。

**目的**是保护实验记录，并确认恢复时的配置符合当前脚本约定。

### 6.4 第 114—171 行：sample_next_token

**输入**是一个位置上全部 V 个候选的 logits，形状 `(V,)`；**输出**是一个 Python
整数 ID。这个函数没有生成整句话，只完成一次选择。

#### 第 119—126 行：数据类型、有效性与温度零

`.float` 将张量转到 float32，通常保持原设备；不表示转成一个 Python `float`。然后
检查全部分数有限。

温度为 0 时直接选择最大分数对应的索引，叫 greedy decoding，贪心解码。`argmax` 返
回最大值的位置，不是最大分数本身；`.item` 从单元素张量取数；`int` 明确返回整数。

这一分支提前 `return`，因此不执行温度除法、top-p 过滤或随机采样。分数相同时，
`argmax` 按其规则选取一个最大值索引，不会自动随机打破平局。

#### 第 128—130 行：正温度与 softmax

先减去最大分数，再除以温度，然后沿最后一个维度做 softmax。这里输入本来只有一个维
度，`dim=-1` 就是整个候选轴。

减去最大值使最大调整后分数为 0，在通常数值范围内减少指数溢出的风险。你本地的
softmax 内部也减最大值；对正常有限值而言，再做一次不改变理论概率。

温度的作用可以通过两候选分数差为 2 来理解：

| 温度 | 调整后的分数差 | 概率倾向 |
|---:|---:|---|
| 0.5 | 4 | 更集中于高分候选 |
| 1 | 2 | 保持原始尺度 |
| 2 | 1 | 候选概率更接近 |

降低温度不是从正文中删词，提高温度也不是增加输出长度。它改变的是每一次选择所使用
的概率分布。

#### 第 132—151 行：top-p 保留哪些候选

top-p 小于 1 时启用核采样：按概率从大到小排列，保留累计概率达到阈值所需的一段前
缀。

`torch.sort` 返回两份结果：排好序的概率，以及这些位置在原数组中的索引。原数组按
token ID 编排，所以后者就是原始 ID。

`torch.cumsum` 得到截至当前位置的累计概率。`previous_mass` 则表示当前位置
**之前**已有多少概率，它由一个零与累计数组去掉末项后的部分拼起来。

`zeros_like` 创建相同形状、类型和设备的零张量；`cat` 沿指定轴拼接。开头的切片保
留长度 1 的轴，而非取得没有轴的标量，因此可以与后面的向量拼接。

#### 一张表读懂阈值跨越

假设 V 为 4，排序后的原 ID 顺序是 2、0、3、1，概率为 0.50、0.30、0.15、0.05，
top-p 为 0.70。

| 排序位置 | 原 ID | 概率 | 截至当前累计 | 当前之前累计 | 保留？ |
|---:|---:|---:|---:|---:|---|
| 0 | 2 | 0.50 | 0.50 | 0.00 | 是 |
| 1 | 0 | 0.30 | 0.80 | 0.50 | 是 |
| 2 | 3 | 0.15 | 0.95 | 0.80 | 否 |
| 3 | 1 | 0.05 | 1.00 | 0.95 | 否 |

第二项使累计概率第一次达到或超过 0.70，所以保留它。若看“截至当前累计是否仍小于阈
值”，就会错过跨越阈值的那一项；当前代码特意使用“之前累计”。

`keep` 是布尔张量，是每个候选的保留标记，不是概率。第一项额外被设为真，明确保证
至少留一个候选。

若阈值恰好是 0.50，第一项已经达到阈值；第二项之前累计等于阈值，不满足严格小于，
就不保留。浮点运算中的边界还要考虑实际表示误差。

#### 第 153—166 行：屏蔽、归一化与抽样

`torch.where` 根据布尔标记逐位置选择：保留则取原概率，否则取 0。它不是把后面的候
选从向量里删除，所以向量长度仍为 V。

将剩余概率除以它们的总和，重新归一化。上述例子保留总量 0.80，因此两个保留项的新
概率为 0.625 和 0.375。

`torch.multinomial` 根据非负权重抽取索引；`num_samples=1` 表示抽一个，返回单元素
整数张量。它返回的是位置，不是概率值。这个 API 本身允许权重未归一化，但此处明确
归一化使语义清晰。参见
[PyTorch multinomial 文档](https://docs.pytorch.org/docs/stable/generated/torch.multinomial.html)。

当前传入的是排序后的概率，抽到排序位置 1 时，对应原 ID 为 0；不能直接把 1 当作最

#### 第 197—207 行：完整历史与本次窗口

循环索引从 0 开始，最多执行 `max_new_tokens` 次。`all_ids` 保存完整历史；

假设窗口长度为 4，完整历史已有 7 个 token，本次模型只看到第 4 到第 7 个，即下标

Python 内层列表是 T 个 ID；再放进一层外列表，构造张量后形成 `(1,T)`。第一维 1 表

#### 第 209—222 行：为什么只取最后一行 logits

模型输出 `(1,T,V)`，含每个输入位置对其后一个 token 的预测。此刻想接在整个 prompt
末尾，因此需要最后一个输入位置的分数。

取值中的 0 选唯一批次，-1 选最后时间位置，冒号保留全部候选。前两个整数下标消去两
个轴，剩下 `(V,)`，恰好满足 `sample_next_token` 的输入要求。

举例说，输入是 A、B、C，最后位置的分数用来选择接在 C 后面的内容；最前面位置的分
数对应 A 后的内容，并非此时要追加的位置。

#### 第 224—229 行：结束 ID 与计数

若抽到 EOS，立即返回，**不把这个 EOS 追加进 `all_ids`**。采样次数是索引加一，因
为索引从 0 起，而实际抽样次数从 1 起。

若是普通 token，就追加到完整历史，下一次模型输入也因此包含新 token。达到上限仍没
抽到 EOS，就返回“达到最大新增 token 数”。

| 情况 | 新增正文 token 数 | 采样次数 | 停止原因 |
|---|---:|---:|---|
| 首次就抽到 EOS | 0 | 1 | 结束 token |
| 追加 3 个普通 token 后抽到 EOS | 3 | 4 | 结束 token |
| 上限 5 次，全部是普通 token | 5 | 5 | 达到上限 |

`max_new_tokens` 在这里限制的是本轮采样尝试，不包含原 prompt 长度；抽到 EOS 的那
次尝试也计入。

#### 当前生成方式的计算特点

每次追加后重新把最近窗口送入模型，当前代码没有维护 KV cache。KV cache 指保存之前
token 的注意力键和值以减少重复计算的缓存；此处知道“没有这项机制”就足够理解为什么
长窗口会有重复前向工作。

窗口滑动不意味着模型获得无限记忆：进程保存完整历史用于显示，但模型每一步仅接收最
后一段窗口。

按中断键都只会显示同样的退出提示”。

`text` 保存原输入，`command` 保存去掉首尾空白后的版本。去空白后等于 `/quit` 就退
出，故命令前后的空格不会妨碍识别。

#### 第 271—291 行：继续旧故事或开始新故事

如果命令为 `/continue`，先要求有历史，再要求上次没有生成 EOS，然后把历史作为新
prompt。

如果不是 `/continue`，先排除全空白输入，然后编码**原始 text**，因此正常故事开头
的首尾空白仍然保留。输入编码包含 EOS 时拒绝本轮生成。

代码没有建立通用命令表：除了两个明确识别的命令，其余非空文字都走故事输入分支，包
括其他以斜杠开头的文字。

`prompt_ids` 在继续分支可以与历史指向同一列表，但 `generate` 随后做了复制，因此
追加内容不会修改用于本轮长度比较的原 prompt。这是前文列表引用知识的实际用途。

#### 第 293—308 行：上下文提示与生成

prompt 超过窗口长度时打印提示，但不拒绝输入。真正的裁剪在生成函数每次迭代中进
行，不是只裁一次初始 prompt。

调用 `generate` 后按返回顺序取得完整 ID、采样次数和停止原因。模型不会在这里自动
把输出写到文件。

#### 第 310—320 行：更新历史与解码

返回长度减去原 prompt 长度得到新增正文 token 数。完整返回 ID 保存为下一次
`/continue` 的历史；停止原因是否为 EOS 决定 `story_ended`。

`tokenizer.decode` 在本地实现中先按 ID 查出各 token 的字节，全部拼接，再统一按
UTF-8 解码。某些 token 只是一个字符的部分字节，所以逐 token 单独解码可能产生替代
符，而拼完整后能还原正常字符。

不过“整体解码”并不保证任意模型采样的字节串都合法。当前解码使用替代错误字符的策
略；如果生成停止在一个未完整的 UTF-8 序列上，末尾仍可能显示替代符。数据准备的逐
段还原检查与任意生成输出的合法性是两回事。

输出的是完整故事，包含用户最初的 prompt 和所有已保留历史，不是只显示本轮新增部
分。最后打印三种统计，让用户知道是否还能继续。

第 324—325 行是直接执行入口。

### 6.7 用会话状态表复核行为

| 当前状态 | 用户输入 | 结果 |
|---|---|---|
| 还没有故事 | `/continue` | 提示先输入开头 |
| 上轮因 token 上限停止 | `/continue` | 将已有历史作为 prompt，再续写一轮 |
| 上轮因 EOS 停止 | `/continue` | 提示另起故事 |
| 任意状态 | 新的正常故事开头 | 生成新故事；成功后用新结果替换历史 |
| 任意状态 | 空白 | 提示输入不能为空，原历史保留 |
| 任意状态 | `/quit` | 退出 |

这里的历史只存在当前进程内，关闭程序后不会因 `last.pt` 而恢复故事历史。模型检查
点与交互会话历史属于不同数据。

## 7. 把三个程序连起来理解

### 7.1 产物之间的关系

| 上游产物 | 谁读取 | 必须保持的对应关系 |
|---|---|---|
| tokenizer 词表与合并规则 | 准备、生成 | 同一 ID 的含义与编码规则应一致 |
| 训练/验证 `.npy` | 训练 | 一维整数 ID，范围与模型 V 相容，长度足够 |
| 编码 `.json` | 供人或额外工具检查 | 记录来源、摘要与处理范围；当前训练脚本没有读取它 |
| `config.json` | 恢复训练、生成 | 重建结构并约束恢复配置 |
| `last.pt` | 恢复训练、生成 | 状态与结构兼容，步数含义一致 |
| `metrics.jsonl` | 供人或分析工具查看 | 每行独立事件，可能包含多次启动记录 |

分词器之于模型类似“编号字典”。如果训练中的 ID 25 表示一种字节串，生成时却用另一
份词表把 25 解释成别的内容，即便张量形状都对，也无法靠正常解码得到预期文字。

当前训练只看整数数组和词表大小，不会主动核对准备脚本写出的 tokenizer 摘要。这是
阅读现有连接关系时应看见的边界，不应把元数据“存在”误认为元数据“被所有下游自动使
用”。

### 7.2 一张完整的类型与形状表

| 阶段中的对象 | 表示 | 类型/形状 |
|---|---|---|
| 读取文本块 | 任意读入片段 | 字符串 |
| 文档段 | 到分隔符为止或最终尾部 | 字符串 |
| 某段编码结果 | 该段的 token ID | Python 整数列表 |
| 某段存储数组 | 紧凑的 ID | 一维小端 uint16 |
| 全部 NPY 数据 | 连续语料 ID 流 | `(N,)` |
| 训练 x、y | B 个窗口及其后移目标 | `(B,T)`，torch.long |
| 模型内部隐藏表示 | 每位置的 D 维表示 | `(B,T,D)` |
| 训练 logits | 每位置的 V 个候选分数 | `(B,T,V)`，浮点 |
| 训练 loss | 平均误差 | 标量张量 `()` |
| 日志 loss | 用于 JSON 的数值 | Python 数字 |
| 生成输入 | 当前一条窗口 | `(1,T)` |
| 下一个位置 logits | 末位置全部候选 | `(V,)` |
| 采样输出 | 一个候选编号 | Python int |
| 生成历史 | prompt 加已追加 ID | Python 整数列表 |

### 7.3 三个程序的“结束”分别意味着什么

准备结束意味着数组构建验证、元数据写入和临时清理走到成功路径；训练结束意味着达到
目标更新次数；一轮生成结束意味着抽到 EOS 或达到本轮上限。三者的停止条件互不相
同。

EOS 在准备阶段作为原文分隔符保留，在训练阶段作为可学习和预测的 token，在生成阶段
作为停止信号。它不是操作系统的文件结束标记，也不是输入流产生的 `EOFError`。

### 7.4 实际路径规则并不完全相同

准备脚本把传入路径解析成绝对路径；训练默认 run-dir 是相对工作目录的路径；生成默
认 run-dir 从脚本位置推导仓库根目录，且默认实验名与训练调试默认名不同。

因此定位“文件找不到”时，先确认程序实际解释的绝对路径。不要先假定所有脚本会去同一
个 `runs` 文件夹、同一个实验名找产物。

## 8. 容易误读的行为与检查问题

这一章不是修改建议清单。目的是让你分清源码已经保证的性质、仍依赖外部条件的性质，
以及观察现象时值得提出的问题。

### 8.1 输入检查不等于所有状态都合法

准备脚本检查 ID 集合与数值范围，训练检查数据类型与范围，生成检查 ID 集合和模型状
态结构。这些都有价值，但没有任何一条单独证明整套系统的语义完全正确。

思考：如果把词表中两个普通 ID 的字节内容交换，而词表大小和 ID 集合都不变，哪些现
有检查会注意到？这能帮助你区分“结构兼容”和“来源一致”。

生成入口检查温度有限且非负、原始 logits 有限，但后续浮点运算也有数值范围。极端小
的正温度或极端大的分数差仍值得观察；“先减最大值”是稳定性措施，不是对任何输入范围
的绝对保证。

### 8.2 已生成最终数组，不一定已有完整收尾记录

准备主流程在写元数据之前完成改名。因此若元数据写入发生异常，最终 `.npy` 可能已经
存在，原始临时文件也可能尚未删除。

思考：遇到失败后，除了扩展名，还应分别确认哪些验证已执行、哪些统计文件存在？为什
么脚本再次运行会拒绝覆盖已有名称？

这份程序没有把多个文件的创建组合成不可分割的事务。事务意味着要么一组动作整体成
功，要么整体撤销；当前代码选择保留失败时留下的内容供检查。

### 8.3 训练恢复与精确重放不同

模型与优化器状态使训练能够延续；已完成次数让学习率调度接上原索引。但随机状态未保
存在当前检查点，重启时种子从头设置，数据采样轨迹未必接上中断前的位置。

思考：如果两次恢复后的模型初始参数相同、学习率相同，但下一批训练窗口不同，那么更
新后参数还应期待逐位相同吗？

生成加载显式指定 CPU 映射；本地训练恢复的 `load_checkpoint` 没有同样的映射参数。
两条加载路径不能直接认定对跨设备恢复有完全相同的行为。

### 8.4 损失下降能够说明什么

人工周期序列上的损失下降，说明模型与训练流程能够利用这类简单规律，不等于证明自然
语言质量。固定验证窗口使比较更稳定，也不等于整个验证集都已测过。

思考：如果训练损失下降但固定验证损失上升，你首先会核对数据来源、采样范围和模型泛
化中的哪一层？现有日志分别能回答什么，不能回答什么？

不要把训练 loss 与验证 loss 的差值全部归因于某一个因素：两者使用不同批次，而且一
份训练事件中的 loss 在该步更新前计算，随后验证在更新后发生。

### 8.5 不同“清理”动作清理不同对象

| 动作 | 改变什么 | 不代表什么 |
|---|---|---|
| `optimizer.zero_grad` | 上一轮梯度 | 不把模型参数重新初始化 |
| `del checkpoint` | 局部对象引用 | 不删除 `.pt` 文件 |
| `del loaded` | 映射数组的局部引用 | 不删除 `.npy` 文件 |
| `raw_path.unlink` | 磁盘临时文件 | 不删除已经生成的最终数组 |
| `model.eval` | 模型模式 | 不删除梯度、不自动关闭自动求导 |

### 8.6 两项性能观察不要凭直觉混淆

内存映射减少一次性大数组复制，但全量 ID 校验仍要读全部 ID。逐文档流式编码避免累
积全量 ID，但单个超长文档仍可能占较大内存。

GPU 工作通常有异步特征，而 `.item` 等把设备结果交给 Python 的动作可能带来等待。
当前代码每步进行有限性检查和标量取值，计时还包含验证、日志及保存等开销，不能把
`elapsed_seconds` 直接当作纯 GPU 算子耗时。

这里理解性能边界即可；本文没有运行性能测试，也没有据此断言哪一行是实际瓶颈。

### 9.6 第一轮检查：能不能分清基本对象

先遮住下一小节，用自己的话回答。

1. 为什么 100 个字符不一定等于 100 字节，也不一定等于 100 token？
2. 一个 ID 为 50000 的 token 在当前原始存储格式中占多少字节？
3. `(2,3,5)` 的 logits 有多少个数？最后的 5 表示什么？
4. `loss.item` 与 `loss.backward` 分别做什么？
5. `model.eval` 会自动关闭梯度记录吗？
6. 生成函数为什么复制 prompt 列表？

#### 对照解释

1. Unicode 码点、UTF-8 字节和词表单位是三种划分。
2. 两字节。存储的是编号，不是把 token 的原文放在这个位置。
3. 30 个数；5 是每个位置可选的 token 类别数。
4. 前者取出单元素 Python 值，后者按计算图求梯度。
5. 不会。模型模式与梯度记录是两个开关。
6. 避免追加改动调用者的列表，并保留本轮 prompt 的原始长度用于统计。

### 9.7 第二轮检查：能不能解释数据准备

1. 分隔符跨过两个读取块时，哪个变量保留前半截？
2. 最后只有几个空格、没有结束分隔符，会不会保留？
3. 为什么在编码完成后才构造 NPY 文件头？
4. `chunk_chars` 与验证时的 `chunk_tokens` 单位有什么不同？
5. 一百万个 uint16 ID 的 NPY 文件是否恰好两百万字节？
6. 只请求 5 段，但原文只有 2 段，为什么最终进度可能不是 100%？

#### 对照解释

1. `pending` 保留尚未交出的尾部。
2. 会，代码没有对尾部做去空白处理。
3. 此时已经知道总 token 数，可以写出正确形状。
4. 前者按文本字符，后者按数组 ID 元素。
5. 原始数据区是两百万字节；NPY 还包含文件头。
6. 请求数是进度分母，实际在文件尾提前停止；结束状态不要求伪装成达到请求数量。

### 9.8 第三轮检查：能不能解释训练日志

1. 为什么长度为 T 的输入要求源数据至少 T+1 项？
2. 默认第一次更新索引是多少，更新后日志 step 是多少？
3. 该条训练日志的 loss 是更新前还是更新后计算的？
4. 检查点记录 50、目标 steps 为 80，还需要几次更新？
5. 为什么验证要保存并恢复 NumPy 随机状态？
6. 当前检查点能否单独保证中断前后的数据采样序列完全连续？

#### 对照解释

1. 目标相对输入向右偏移一项。
2. 更新索引 0，日志 step 为 1。
3. 更新前的前向计算所得，记录发生在更新完成后。
4. 30 次。
5. 本地数据采样用 NumPy，验证不应额外推进后续训练采样所见的状态。
6. 不能；当前没有保存那些随机状态。

### 9.9 第四轮检查：能不能解释生成

1. 为什么输入 `(1,T)`，最后用于采样的却是 `(V,)`？
2. 温度为 0 时，top-p 是否参与选择？
3. top-p 为 1 时，是否必定取概率最大的 token？
4. 排序索引与 token ID 为什么必须分别保留？
5. 连续生成 2 个普通 token 后抽到 EOS，正文新增数与采样数分别是多少？
6. 为什么超出窗口的早期故事仍能显示，但模型不一定能利用？
7. 为什么所有 token 字节拼好后再解码？

#### 对照解释

1. 模型输出所有位置的分数，当前只选唯一批次的最后位置，保留候选轴。
2. 不参与；函数在贪心分支提前返回。
3. 不必；它跳过截断，但正温度时仍随机抽样。
4. 排序改变位置排列，抽样得到的是排序后的下标，需要映射回原始词表。
5. 正文新增 2，采样 3。
6. 完整历史用于显示，送入模型的只是尾部窗口。
7. 单个 token 的字节不一定构成完整 UTF-8 字符，拼接后再解码能避免人为拆坏字符。

### 9.10 怎样判断自己开始真正读懂了

不要求默写全部 API。更有用的检查是：任选一个函数，不看本教程，用自己的话说出输入
类型、输出类型、副作用和失败前提；再回源码逐项核对。

进一步可以只看一段已有调用，说明传入的对象从哪里来，返回后交给谁；遇到张量写出每
个轴的含义；遇到文件操作说明是否会改变磁盘；遇到数字说明单位；遇到循环说明计数在
动作前还是动作后增加。

如果某处说不清，就回到对应章节，而不是先背下一行。独立练习时，依照课程允许的范围
自行完成实现，使用这里的形状、计数和还原性质作为理解检查，不把现成组织流程当成必
须原样模仿的模板。
